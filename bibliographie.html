Bibliographie

Dans cet article, je partage quelques lectures qui m'ont été utiles dans ma pratique du développement logiciel. Ces ouvrages couvrent divers aspects du développement, de la conception à la gestion de projet, en passant par les bonnes pratiques de codage.

Les premiers livres à lire

Coder proprement par Robert C. Martin

Pour moi, c'est le premier livre à lire lorsqu'on souhaite augmenter la qualité de son code. Il présente les bonnes pratiques de codage avec des explications claires et des exemples concrets pour chaque principe. Il est très accessible et peut servir de support pour des cours. Le relire occasionnellement est bénéfique. J'ai apprécié la simplicité et l'efficacité des principes qui peuvent être appliqués dans n'importe quel langage de programmation.

Test-Driven Development by Example par Kent Beck

Un livre sur le TDD (Test Driven Development) qui consiste à écrire les tests unitaires en même temps que l'implémentation. Certaines fois, on parle d'écrire les tests avant l'implémentation ce qui peut être mal interprété. Lorsque j'ai testé cette approche pour la première fois (après avoir lu un court article sur un blog), étant habitué à écrire les tests après l'implémentation, j'ai voulu écrire la totalité de mon test avant l'implémentation ce qui est à l'opposé de la méthode TDD. Cette méthode propose d'écrire le code par itération de cycles très courts en écrivant le test et l'implémentation en parallèle. Le but est d'avoir un retour (feedback) permanent sur le code écrit afin de détecter rapidement les erreurs. Même si on n'adopte pas la méthode dans son ensemble, il y a de nombreux conseils à prendre pour améliorer notre efficacité.

La méthode TDD est vendue comme étant très efficace car on écrit moins de code, on détecte les erreurs plus rapidement, on a un code mieux architecturé et, bien sûr, avec une excellent couverture de tests. Le lecteur est pris par la main pour comprendre la méthode TDD à travers des exemples concrets. Un de mes livres préférés, si ce n'est mon préféré. À mettre entre toutes les mains.

Un épisode de l'excellent podcast IFTTD sur un retour d'expérience de l'utilisation du TDD : https://www.infoq.com/fr/podcasts/tdd-retour-experience/

Refactoring, Comment améliorer le code existant par Martin Fowler

Un livre sur le refactoring, c'est-à-dire la modification du code existant pour l'améliorer sans changer son comportement. Le refactoring est une pratique essentielle pour maintenir la qualité du code au fil du temps. Le livre présente un très grand nombre de techniques de refactoring avec des exemples concrets. Chaque technique est discutée pour savoir quand et comment l'appliquer. Le livre est littéralement une liste d'exemples de codes avec toutes les étapes de transformation ce qui le rend difficile à lire de bout en bout. J'ai apprécié ce niveau de détails qui montre comment modifier du code, pas à pas, en prenant un maximum de précautions. Les motivations de chaque refactoring sont aussi très précieuses et décrivent des bonnes pratiques de codage.

Effective Software Testing, A Developer's Guide par Maurícia Aniche

Un livre sur comment rédiger des tests unitaires de qualité. Il explique les différents types de tests unitaires, les techniques utilisées en programmation objet pour l'écriture des tests et comment utiliser les librairies de tests pour paramétrer les entrées. Si vous n'avez jamais écrit de tests unitaires, il y a peut-être des livres plus abordables. J'ai trouvé ce livre très complet et bien structuré, avec des exemples concrets.

À lire après quelques expériences en développement

Design Patterns, Elements of Reusable Object-Oriented Software par Erich Gamma, Richard Helm, Ralph Johnson, John Vlissides

Un excellent livre sur la conception de logiciel avec la programmation orientée objet. Il présente 23 patrons de conception (design patterns) qui sont des solutions réutilisables à des problèmes courants. Chaque patron est expliqué en détail avec des exemples concrets. J'ai apprécié les argumentations sur les avantages et les inconvénients de chaque patron qui montre que la conception de logiciel est un exercice d'équilibre et de compromis. Même si on ne souhaite pas utiliser les patrons de conception, le livre est une mine d'or pour comprendre les principes de la conception orientée objet.

Pour apprendre la programmation

Python pour les Kids, la programmation accessible aux enfants par Jason R. Briggs

Si vous souhaitez apprendre la programmation, ce livre est une excellente introduction. Il est destiné aux enfants mais il est aussi très accessible pour les adultes débutants. Vous irez probablement plus vite mais vous aurez la chance de bien comprendre toutes les étapes pour créer votre premier logiciel. Je ne sais pas si c'est le meilleur livre pour débuter mais vous trouverez certainement les réponses à de nombreuses questions. Il y a des exemples pour illustrer toutes les étapes et vous guider pas à pas et deux exemples complets de jeux à coder.
